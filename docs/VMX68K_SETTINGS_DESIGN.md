# VMX68K 設定GUI: SX標準部品の調査

2026-11-14。配置と画面構成は現行を維持する。前案の配置変更、子画面への再構成、
パス欄の拡幅は撤回。実装変更はまだ行っていない。

## 確認した一次資料

ローカルのWorkroom SX-68K（SHARP、1994年）の以下を確認した。

- `workroom1/INCLUDE/CONTROL.H`: 標準CDEF一覧とパートコード。
- `workroom1/INCLUDE/SXDEF2.H:251–260`: 標準部品の寸法定数。
- 基礎編 `数値調整ﾎﾞﾀﾝ/ADJUST.C:7–35,190–203`: 用途、形状、サイズ、操作の説明と生成例。
- 基礎編 `文字ボタン/BUTTUN.C:7–15,183–196`: ボタンの描画と生成寸法。
- 基礎編 `ｽﾗｲﾄﾞﾎﾞﾘｭｰﾑ/SLIDE.C:7–24`: 線形的な値への使用と操作範囲。
- 基礎編 `複数ｺﾝﾄﾛｰﾙ/PCONTROL.C`: 複数種類の部品を並べる例。
- 実用編 `小遣い帳/CSMAIN.C:249–256,735–759`: 数値調整ボタンに日付を表示する例。
- 実用編 `ペイント/GPSUBWIN.C:137–192`: RGB調整にスライダーと数値調整ボタンを併用。
- 基礎編 `ドラッグ/DRAG.C:321–359`: Filerのファイルアイコン受け取り例。

## 標準選択部品

CONTROL.Hの標準CDEFは、文字ボタン、ラジオボタン、チェックボックス、
スライドボリューム、数値調整ボタン、4種類のスクロールバー。
この一覧にドロップダウン選択ボックス／コンボボックスはない。
これは標準Control Man部品の範囲での確認であり、SXでメニューそのものが使えないという意味ではない。

数値調整ボタン `CI_ADJBTN` (CDEF ID $14、proc ID $140) は、
**左にタイトル表示ボックス、右に2つの矢印ボタン**という標準部品。
ADJUST.Cは離散値への使用を説明する。横幅を増やすとタイトル部分が広がるが、
矢印自体の寸法は変わらない。高さを増やしても描画は高くならず、クリック判定だけが広がる。

増減はC_INDEC / C_ININCを処理し、値と表示をCMValueSet / CMTitleSetで更新する。
タイトルはアプリが指定できる。小遣い帳では「--月--日」から実際の日付へ更新しており、
整数の10進表記だけに制限されない。
数値入力用途ではタイトル部分(C_INTITLE)のクリックで直接入力するのが標準的と説明されるが、
基礎サンプル自身はその処理を省略している。部品が自動でTEditになるわけではない。

スライダー `CI_SLDVOL` は線形的な値に用いるとSLIDE.Cが説明する。
最大速度を含む周波数の列挙や、STD / FD / SCSI / ROMの列挙は数値調整ボタンが適する、
というのが今回の資料に基づく実装方針。メモリのスライダーは維持する。

## 寸法

| 部品 | SDK定数 | 意味 |
| --- | --- | --- |
| 文字ボタン | CHRBTN_H=6, CHRBTN_V=19 | サンプルの幅は6＋文字幅、高さ19 |
| 数値調整ボタン | ADJBTN_H=48, ADJBTN_V=18 | サンプルの幅は48＋表示文字幅、高さ18 |
| スライダー | SLDVOL_H=14, SLDVOL_V=16 | つまみは固定寸法、溝を指定幅に合わせる |
| ラジオ | RADBTN_H=32, RADBTN_V=9 | 標準寸法定数 |
| チェックボックス | CHKBOX_H=13, CHKBOX_V=13 | ラジオとは異なる標準部品 |

文字ボタンサンプルの「実行」は幅6＋12×2=30、高さ19。
文字ボタンは指定した矩形で描画されるため、大きなボタンを作ること自体はAPI違反ではない。
ただし現行の設定84×26、取消92×26、詳細110×26は、このサンプルの寸法感と大きく異なる。
ボタンの位置・並びは維持し、文字幅とSDKの余白を基準に寸法を合わせる。
以前のVMX68Kの18px高を唯一の標準とした説明は訂正する。

現行スプライトチェック項目は33×9の矩形を使っている。
D_CHKBOX自体の描画とクリック領域が13×13に整合するかも実画面で確認する。

## 現行実装との差と変更範囲

`config_dialog_items()` の周波数・起動装置はD_CHRBTNに▼のD_STCTXTを重ねている。
`config_frequency` / `config_boot` は `config_selector` を呼び、
`choice_items()` のボタン列を別DLOGとして開く。標準ドロップダウンの呼び出しではない。

変更方針:

- 現行の項目順、配置、設定／新規の共通画面、詳細画面は維持する。
- 周波数と起動装置の現在位置に標準CI_ADJBTNを置く。独自▼と選択肢DLOGを外す。
- 周波数はCPUごとの既存選択肢をインデックスで選び、表示は10MHz等とする。
- 起動装置も既存のSTD、FD0–3、SCSI0–7、ROMを選ぶ。共有モードでは標準の無効表示。
- ROMアドレス編集への入口は既存の編集機能を残す形で詰める。
  矢印でROMを通過するだけでモーダル画面が開く挙動にはしない。
- 数値調整ボタンは装飾だけでなくC_INDEC / C_ININCを区別して扱い、
  範囲端、押下中の表示、リピートもWorkroomの処理を基準にする。
- 設定、取消、詳細などはSDKの文字ボタン寸法に合わせる。
- メモリの部品と値表示は維持し、つまみの操作・描画を標準実装と照合する。
- ドロップ対応と保存／取消の仕様は引き続き維持する。

## ドロップの調査状況

現行のconfiguration / new-setup / settings-dropの既存テストは通過している。
ユーザーが報告した失敗は未再現・未修正。

WorkroomのDRAG.Cはセルリストをロックし、Filerのアイコン種別、単一セル、
ファイル属性を確認してTSISRecToStrで完全パスを得る。成功時はTS_FINISH、
拒否時はTS_PUTBACKで終了し、ロックを解除する。
現行VMX68KはTSCellToStrを使うため、まずこのAPIの契約と戻り値、対象セルの扱いを
照合する。APIが違うというだけで原因とは断定しない。入力中TEditとの同期と、
非アクティブ時・複数行のドロップも実際のFiler操作で確認する。
